# dsh-verifier-brain 下一迭代计划（ITERATION PLAN）

> 版本基线：v0.1.0（当前已装配版）
> 制定日期：2026-08-21
> 主题：**让分数可信**——自适应验证缩放（Adaptive Verification Scaling）
> 后续：证据链自动化 → /bestofn 一键命令

---

## 〇、一句话定位

下一迭代不加新功能，而是修"可信度"：**单次评估的分差落在噪声区间时，系统自动多评几遍取平均，并把"这个结论评了几遍"如实告诉用户。**

---

## 一、动机（全部来自本机实战数据）

### 1.1 三次被噪声咬伤的实录

| 时间 | 场景 | 现象 | 后果 |
|---|---|---|---|
| LRU Best-of-N | 三版分差最大 0.08 | 分数语义需要向用户额外解释"这是相对信号" | 排名说服力打折 |
| 马里奥 Best-of-N | A=0.5349 vs B=0.5066，分差 0.028 | 噪声分差被当有效排名；B 版每帧崩溃都没被排名信号提示 | 错误冠军成为合并底子 |
| 111.txt 首评 | A"获胜"（后经视觉补测翻案） | 证据缺失 × 单次评估双重失真 | 用户质疑结果可信度 |

### 1.2 根因：K=1 时两个统计机制完全失效

官方 LLM-as-a-Verifier 的重复评估（n_evaluations）机制同时做两件事：

1. **抹平随机波动**：temperature=1.0 下每次采样有抖动，K 次平均收敛
2. **抵消位置偏差**：官方实现里奇数轮自动交替 A/B 槽位（"odd reps swap the prompt slots, so positional bias cancels"）——**K=1 时该机制完全不工作**，模型偏爱某槽位的天性直接进入分数

当前默认 `n_evaluations=1` 是第一轮实战超时事故后的急救措施（官方默认 K 偏大曾把同步桥拖到 300s 超时），代价是上面两条机制被整体关闭。

### 1.3 为什么不用"默认调大 K"解决

- K=3 全局生效 → 所有评分成本 ×3、时延 ×3，而大多数场景（分差显著）根本不需要
- 论文的"验证缩放"本意就是**算力堆在不确定处**，固定 K 是对这条轴的误用
- 正确形态：K=1 快筛 → 分数接近时按需升级

## 二、方案设计

### 2.1 核心逻辑

```
评分执行（K=1，成本与现状完全相同）
  ↓
计算 margin（select: 前二名分差；compare: |reward_a - reward_b|）
  ├─ margin > ESCALATE_THRESHOLD（默认 0.15）
  │     → 直接采信，返回结果 + {escalated: false}
  ├─ 0.03 < margin ≤ 0.15
  │     → 自动升级重评（select: n_evaluations=3 由官方锦标赛内部处理；
  │       compare: 手动调 K=3 且奇数轮交换 candidate_a/b 槽位、回报后换回——
  │       官方只在 select 锦标赛内部做槽位交替，裸 compare 必须自己做）
  │     → 取平均后返回 + {escalated: true, k_used: 3, margin_before, margin_after}
  └─ margin ≤ 0.03（flat，已有机制）
        → signal:"flat" + 提示 compare 复核 / 标准细化
```

### 2.1b 方向一致性判定规则（评审意见 2.2，P0）

| 场景 | 判定 | 输出行为 |
|---|---|---|
| compare ×3 | 胜者 3/3 一致 | 取平均分，标注"3/3 一致" |
| compare ×3 | 胜者 2:1 | 取平均分，标注"2/3 一致，建议谨慎参考" |
| compare ×3 | 胜者 1:2（翻转） | **不取平均**，返回全部 3 组原始分数，标注"信号不稳定，建议人工复核" |
| select ×3 | 第一名全部相同 | 取平均排名/分数 |
| select ×3 | 第一名不一致 | **不取平均**，返回 3 次独立排名，标注"第一名不一致，建议人工复核" |

### 2.1c 缓存与水位线（评审意见 2.1 / 2.4）

- **缓存键显式加入 `n_evaluations`**：K=1 首评与 K=3 升级结果并存，审计时可见"首评 vs 升级后"差异；结果附 `cached: true/false`
- **异步预算水位线**：`history.jsonl` 已持久化每次评分的 `duration_ms`——用**真实历史耗时**动态估算升级开销（评审建议的"3-5 秒/次"与本端点实测的 30~120 秒/次不符）；当 `剩余预算 < 预估升级耗时 × 1.2` 时降级 K=2。由于 compare 升级自带手动换槽（2.1），**K=2（1 正 + 1 反）同样抵消一次位置偏差**，无需评审建议的"可信度低于 K=3"警告，仅注明 `k_used: 2`

### 2.2 改动面（全部在桥/工具层，无新依赖）

| 位置 | 改动 |
|---|---|
| `src/tools.ts` | compare/select execute 返回前检查 margin；低于阈值时以 `n_evaluations=3` 重跑（绕过缓存，缓存键加入 k）；合并两次结果取均值；结果附升级元数据 |
| `src/index.ts` + `cordis.patch.yml` | 新增配置：`autoEscalate`（默认 true）、`escalateThreshold`（默认 0.15）、`maxEscalateK`（默认 3） |
| `src/prompt.ts` | "Reading the scores"段落更新：描述自动升级行为，agent 无需再自行判断是否复核 |
| `bridge` | 无改动（n_evaluations 本就透传官方 API） |

### 2.3 成本护栏

- 升级只发生在"分数接近"的场景——按今天实测，触发率约 1/3 以下，**期望成本增幅 < 1.5×**，远低于全局 K=3 的 3×
- 大 N select 走异步任务（30min 预算）：升级前查水位线——用 `history.jsonl` 持久化的真实单次耗时动态估算，当 `剩余预算 < 预估升级耗时 × 1.2` 时降级 K=2（compare 升级自带手动换槽，K=2 同样抵消一次位置偏差，仅注明 `k_used: 2`）
- `autoEscalate: false` 一键回到现状

### 2.4 结果呈现规范（吸取"分数语义解释成本"教训）

升级发生时，render 与历史记录必须包含：

```
⚠️ 分差处于噪声区间，已自动升级为 3 次评估取平均
   margin: 0.028 → 0.114（升级后）
   结论可信度：3 次独立评估方向一致（3/3）
```

方向一致性按 2.1b 判定表执行：翻转场景**不取平均**，返回全部原始分数并标注"信号不稳定，建议人工复核"——**不许静默取平均了事**。结果一律附 `cached: true/false` 标注实时计算还是缓存命中。

## 四、第二步：证据链自动化（本迭代验收后启动）

目标：把已人工验证的链路变成评分输入标配。

```
可运行产物 → 无头冒烟测试（cdp_mario_smoke.cjs 泛化）
  ├─ 崩溃 → 候选直接出局（分数 0，附错误栈）
  └─ 通过 → 截图 → 多模态模型（ox-alpha，图像输入）写结构化视觉/状态描述
            → 描述 + 功能摘要一起交给 verifier 评分
```

要点：
- 冒烟泛化**限定两类**（评审意见 2.5，控制 M3 工作量）：① HTML 文件——CDP 打开，采集控制台错误+截图；② Node.js 脚本——child_process 执行，采集 stdout/stderr+退出码。其余产物类型标记"实验性"，文档明列支持范围
- 视觉描述模板固定（色彩/氛围/细节密度/风格化/第一印象五维），保证跨候选可比
- 证据与摘要拼接时**明确标注来源**（"以下为运行时观察，非候选自述"）

## 五、第三步：/bestofn 一键命令

固化整条链：`/bestofn <任务> [N]`
→ 队长派 N 成员完整实现（策略铁律防分工切面）
→ 每个产物冒烟测试（崩溃出局）
→ 幸存者证据+摘要 → verifier select（含自适应 K）
→ 整合代理合并 → 合并版冒烟 → compare 门禁
→ 交付 + 全程分数报告

前置依赖：第二节的升级机制 + 第四节的证据链。
